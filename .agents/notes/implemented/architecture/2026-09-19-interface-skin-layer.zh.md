# Agent Note: 界面皮肤层

Status: implemented

[English](2026-09-19-interface-skin-layer.md) | 中文

## Problem

产品希望用户能用上对话设计稿中的材质界面，同时不放弃现有界面。两者的差异不止配色：设计稿把对话面板内嵌进圆角玻璃卡片、让侧栏浮在渐变背景场上，并重写了输入框、消息气泡与标签栏。现有界面必须在未选择新版的用户处保持原样，而这个选择必须是按用户保存的设置，而不是部署档位。

“第二套 shell”是最直观的选择，也是错误的选择。界面并非单个组件：`ui-sidebar`、`ui-conversation`、`ui-chat` 与设置类插件各持一部分，且各自持有业务状态（工作区树、输入框状态机、会话投影）。平行 shell 要么复刻全部这些逻辑，要么以更低优先级遮蔽每一个 slot 占用者。

## Decision

由单个客户端包 `@deepseek-ai/dsh-client-ui-skin` 持有该选择并把它投影到文档上。

持久值存放在 `ui-skin` 分区（默认 `material`），由宿主半注册、由通用分区的“界面”项写入。`SkinRuntime` 持有当前取值，向设置项的 store 发布不可变快照，并负责该取值在文档层面的全部写入：`document.documentElement` 上的 `data-dsh-skin` 属性、通过 `ctx.theme.overrideTokens` 写入的一层别名 token，以及背景场元素。宿主半会在 shell 挂载前把持久值发布到根元素上，运行时以该发布值作为起点，因此页面已画出的界面与运行时投影的界面保持一致。选择 `classic` 会撤销 token 层与背景场，并让属性标明当前是经典界面，因此卸载本插件或选择经典时，界面与之前完全一致。

新版样式表的每条规则都要求根属性，因此该样式表虽是全局的，作用域却是选中的界面本身。规则通过现有组件渲染所在的 slot 座位及其稳定类名后缀抵达它们；配色轴则走别名 token 层，因此菜单、浮层与卡片无需复制样式即可跟随新版配色。背景场是普通 DOM——一个固定元素，CSS 渐变之上是一块运行设计稿流动图案着色器的 WebGL2 画布——因为它不承载产品状态，也不该让任何 React 树为之重挂载。

## Alternatives considered

**以优先级遮蔽 slot 占用者的第二套 shell 包。** slot 注册表支持在不同优先级上遮蔽，对于值得重写的部件它仍是首选机制。此处不采用，是因为界面横跨四个特性包，而这些组件各自持有业务状态。

**在主题注册表上增加“界面”轴。** 已注册主题只能写别名 token，而新版界面需要 token 层不承载的结构：面板内边距与圆角、背景模糊、背景场、标签指示条。因此皮肤用 token 层负责配色，用限定作用域的样式表负责结构。

**就地改写现有组件。** 在 `ui-sidebar`、`ui-conversation` 与 `ui-chat` 内部分支，会把第二套视觉约定塞进每个组件，并使此后对任一套界面的修改都变成对两套的修改。

## Consequences

样式表的选择器是一份需要维护的耦合：重命名某个 slot 或组件类名后缀时需要同步更新样式表，失配时浏览器 e2e 用例会失败。已注册主题与本皮肤可能写入同一别名 token，后写入的层按 token 生效，因此注册了主题的部署应预期新版配色位于其之上或之下取决于注册顺序。背景场把设计稿的流动图案着色器移植到 WebGL2 画布上，并保留 CSS 渐变层；设计稿中的 90px 格网与跟随指针的光晕都被有意去掉，不支持 WebGL2 的浏览器只保留渐变层，冷启动在承载样式表的插件包抵达前仍是经典界面。
